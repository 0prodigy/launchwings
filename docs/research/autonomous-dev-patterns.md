# Autonomous coding agent / 24-7 dev-loop patterns

Scope: confirm/extend MISSION.md §1-4 vs current expert practice for an unattended Claude Code loop. Sources constrained to the named set. Pulled 2026-05-29.

## 1. Patterns we adopt

1. **One thing per loop + deterministic stack.** Huntley's Ralph loop: one process, one prompt, one task per tick, always re-loading `specs/*` + `fix_plan.md`. "Ralph is monolithic. Ralph works autonomously in a single repository as a single process that performs one task per loop." Lands as MISSION §1 step 1 — keep tick = one slice, never two. [ghuntley.com/ralph](https://ghuntley.com/ralph/)
2. **Specs are the spec, not the prompt.** Huntley: "There is no such thing as a perfect prompt"; durable artefacts are spec files, the prompt just points at them. Anthropic echoes: write a self-contained spec, fresh session executes. Our equivalent: `docs/decisions/0006-*` + per-feature evals re-loaded each tick. [Anthropic best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
3. **Verification gate in-loop — evidence, not assertion.** Anthropic: "Claude stops when the work looks done. Without a check it can run, 'looks done' is the only signal available… Give Claude something that produces a pass or fail and the loop closes on its own." Already MISSION §1 step 4; tighten so the tick refuses to advance without a captured pass/fail artefact (Rule 12). [Anthropic best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
4. **Capture the *why* of each test inline.** Huntley: "ask Ralph to write out the meaning and the importance of the test… future loops will not have the reasoning in their context window." New tests need a docstring stating the business invariant. [ghuntley.com/ralph](https://ghuntley.com/ralph/)
5. **Single-threaded main agent; subagents only for reads/verification.** Cognition (Devin): "running multiple agents in collaboration only results in fragile systems… decision-making ends up too dispersed." They note Claude Code's subagents are deliberately read-only. Confirms MISSION C3. [cognition.ai/blog/dont-build-multi-agents](https://cognition.ai/blog/dont-build-multi-agents)
6. **Context is the budget.** Anthropic: "context window is the most important resource to manage." Huntley: quality clips ~147-152k of the 200k window. Operational: `/clear` between ticks, expensive reads → subagents, re-load specs each tick. [Anthropic best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
7. **Writer/Reviewer split in fresh context.** Anthropic: "a fresh context improves code review since Claude won't be biased toward code it just wrote." Formalise §1 step 5: reviewer runs in a fresh session, not a continuation. [Anthropic best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
8. **Read-only conventions file, prompt-cached.** Aider's `CONVENTIONS.md`: `/read` marks it read-only and cacheable. Split the stable block of our `CLAUDE.md` into an immutable include so cache stays warm across ticks. [aider.chat/docs/usage/conventions.html](https://aider.chat/docs/usage/conventions.html)

## 2. Patterns we reject

- **Background / fully detached agents (Cursor/Devin defaults).** Steipete: "Still don't see how this could be moved to background agents. I steer the models a lot as I notice them drifting off." Conflicts with Rule 12 / A10 — we keep founder-visible diffs and checkpoint-gated resume. [steipete.me / optimal-ai-development-workflow](https://steipete.me/posts/2025/optimal-ai-development-workflow)
- **Multi-agent collaboration.** Cognition: such libraries "actively push concepts which I believe to be the wrong way of building agents." MISSION C3 already aligns. [cognition.ai/blog/dont-build-multi-agents](https://cognition.ai/blog/dont-build-multi-agents)
- **Large MCP surface.** Steipete removed his last MCP — "Claude sometimes would go off spinning up Playwright unasked when it could simply read the code." Prefer CLIs (`gh`, `psql`, `pnpm`, `vercel`) plus a one-line CLAUDE.md hint. [steipete.me](https://steipete.me/posts/2025/optimal-ai-development-workflow)
- **Massive subagent fan-out for build/test.** Huntley: "fan out to a couple of hundred subagents… you'll get bad form back-pressure. Use as many subagents for searching… but only a single subagent for validation." [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- **Edit-apply two-model split.** Cognition: the small applier "would misinterpret the instructions… today, edit decision-making and applying are more often done by a single model in one action." We use direct Edit/Write — keep. [cognition.ai/blog/dont-build-multi-agents](https://cognition.ai/blog/dont-build-multi-agents)

## 3. Gaps in MISSION.md §1 to close on return

1. **Token / $ ceiling per tick.** No hard cap today. Add per-tick soft budget (~30k generated tokens / ~$1) and a session cap; on breach, summarise + checkpoint to HANDOFF.md rather than silently continuing. Aligns with Rule 6.
2. **Three-strikes detector as a hook.** Anthropic: "hooks are deterministic and guarantee the action happens." Promote Rule 10's three-strikes from doctrine to `.claude/hooks/three_strikes.sh` scanning recent tool errors and forcing STOP. [Anthropic best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
3. **Eval-first enforcement gate.** §1 step 2 says evals first, but nothing blocks an LLM-touching slice from shipping evalless. Add a pre-commit hook: any change under `packages/agents/**` requires a same-commit change in `evals/<feature>.{yaml,jsonl}`.
4. **Persistent supervisor, not in-session loop.** True 24/7 needs a Ralph-style `while true; do claude --resume …; done` with backoff, so a fresh process replaces in-memory session each tick. Caveat (steipete): kill-switch + visible diff before merge are non-negotiable.
5. **Spec-drift audit every N ticks.** Huntley: lost a month to a doubly-defined keyword in his spec. Schedule a periodic "audit `docs/decisions/*` vs current code" subagent run (every 20 ticks or daily) emitting an issue list only — no edits.

## 4. Cost discipline — what others report

Public $/day numbers for unattended loops are thin and self-reported. Huntley says Ralph just needs *tokens* — "throw them at them" — and built a self-hosting compiler on it without publishing a daily spend; the de-facto ceiling is the Claude Max rate limit, which Steipete also hits: "new rate limits will go into effect August 28 and that'll definitely suck. Guess I'll just pay up." Steipete is the only constrained source quantifying parallelism — normally 1-2 agents, "~4 seems to be the sweet spot" for cleanup/tests/UI — and treats context as scarcer than $. Implication for LaunchWings: don't budget on $/day yet — budget on **tokens-per-tick** and **rate-limit headroom**; surface a daily `ccusage`/API-dashboard line in HANDOFF.md so the founder sees burn on resume.
